# Подготовка обмена с 1С:УНФ

В этой версии есть серверная диагностика OData. **Создание счетов в 1С пока не реализовано.** Счёт АТЛАС не считается документом 1С, даже если он напечатан или выгружен в файл. Совпадение названий товаров не заменяет сопоставление ссылок 1С.

## Если база опубликована только по HTTP

Администратор размещает HTTPS reverse proxy/шлюз рядом с сервером 1С. Прокси обращается к HTTP-публикации по локальной сети, а АТЛАС — к защищённому адресу прокси. Либо на веб-сервере 1С настраивается HTTPS. Настройка шлюза в этом проекте не выполнена. Пароли нельзя вводить в заявку, прайс, публичный репозиторий или отправлять в чат. Пароль от учётной записи администратора для обмена не нужен.

HTTP-адрес веб-клиента сам по себе не подтверждает доступность OData. Администратор включает стандартный интерфейс при публикации и предоставляет отдельному пользователю чтение только нужных справочников и метаданных. Доступ на запись добавляется после проверки сопоставлений на тестовой базе.

## Серверные настройки

Настройки задаются оператором развёртывания в защищённых переменных окружения Workers; интерфейс не принимает произвольный URL от посетителя:

- `ONEC_OWNER_ID`: идентификатор владельца АТЛАС, которому принадлежит подключение.
- `ONEC_ODATA_URL`: HTTPS URL, заканчивающийся `/odata/standard.odata/`.
- `ONEC_ALLOWED_ORIGIN`: точный разрешённый origin этого URL, без пути, параметров и встроенных паролей.
- `ONEC_USERNAME` и `ONEC_PASSWORD`: отдельный пользователь обмена; либо `ONEC_BEARER_TOKEN` для собственного шлюза. Не задавать оба способа одновременно.

Пример адреса: `https://bridge.example/unf/odata/standard.odata/`. Это образец, не действующее подключение. Настройки не содержат URL или учётных данных конкретной компании. При нескольких владельцах потребуется хранилище раздельных подключений: текущая конфигурация намеренно доступна только одному `ONEC_OWNER_ID`.

`GET /api/onec` возвращает состояние настройки без сети. `POST /api/onec` при аутентификации и совпадающем Origin делает один GET `$metadata`. Перенаправления запрещены, таймаут 10 секунд, ответ ограничен 2 МБ. Ни URL, ни учётные данные, ни тело ответа при ошибке не возвращаются клиенту. Результат `metadata_available` означает только чтение схемы, а не готовность создавать документы. `canWrite` всегда `false`.

## Что нужно до создания первого счёта

1. Получить реальную схему `$metadata` именно используемой версии УНФ и состав опубликованных объектов. Имена документов и реквизитов нельзя угадывать.
2. Прочитать доступную номенклатуру, организации, единицы измерения, контрагентов, договоры и пользователей. Хранить подтверждённые соответствия по стабильным ссылкам 1С.
3. Точное совпадение артикула и характеристик предложить первым; похожее по смыслу название показывать как кандидат на согласование. Проверять единицу, упаковку, размер, модель и НДС. Не выбирать аналог автоматически для выставления счёта.
4. Пользователь выбирает покупателя. Ответственного сопоставить с записью Михаила Булыгина в справочнике 1С; текстовое имя в АТЛАС не является ссылкой 1С.
5. На тестовой базе проверить обязательные реквизиты конкретного документа, организацию, договор, налоги, валюту и округление. Обычная проверка заполнения при OData-записи платформой не гарантируется, поэтому её должен обеспечивать адаптер.
6. Реализовать создание черновика с ключом идемпотентности и сохранением возвращённого Ref_Key/номера, затем повторное чтение и сверку сумм. Пока этот этап не реализован, нельзя показывать «Счёт создан в 1С».
