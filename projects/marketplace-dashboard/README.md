# Пульт: локальное приложение

Запуск из этой папки: `node server.cjs`. Нужны Windows и Node.js 20 или новее.

Адрес: http://127.0.0.1:4317/

Главная страница показывает реальные данные пяти магазинов: общий каталог, поиск, фильтры себестоимости и остатков, карточки товаров, CSV и динамику начислений Ozon. Настройки подключения — /connections.html. Старый демонстрационный экран сохранён по адресу /demo.html; зеркало работает отдельно.

Ключи зашифрованы Windows DPAPI для текущей учётной записи и сохраняются в .private/stores.json. Снимки данных находятся в .private/data-*.json; не включайте эту папку в публикацию сайта. Папка исключена из git. Сервер доступен только на этом компьютере.

Ozon: товары, остатки, ежедневные начисления за 30 календарных дней, включая текущий неполный день. Финансы используют /v1/finance/accrual/by-day с последовательным чтением всех страниц.

Wildberries: карточки, остатки складов WB и детализация ежедневных финансовых отчётов. Обновление зависит от задержек публикации отчётов площадкой. Себестоимость Ozon импортируется вместе с товарами; нулевые значения отмечены для проверки. Для Ozon добавлена оценка прибыли до налогов по текущей себестоимости; бухгалтерская чистая прибыль требует внешних расходов и истории себестоимости. Отдельные рекламные отчёты ещё не импортируются.

После перезапуска сервера обновите страницу браузера. Завершённые данные сохраняются; незавершённый импорт можно запустить кнопкой «Обновить данные». Во время импорта не останавливайте сервер.

Проверки: `node --test test/*.test.cjs`. Кнопка «Проверить обновления» перечитывает локальные снимки; кнопка в карточке магазина запускает импорт из площадки.
В рабочем обзоре по умолчанию скрыты архивные товары Ozon и товары со статусом «Не продаётся». Переключатель позволяет вернуть полный каталог; выбор хранится в браузере. Фильтр влияет на товарные показатели, таблицу и CSV. Исторические финансы сохраняют все операции. Статусы WB не импортированы, поэтому по этому признаку WB не скрывается.
# Управление товарами

Раздел `http://127.0.0.1:4317/manage.html` работает с реальными товарами подключённых магазинов. Ссылка есть в боковом меню и карточке товара основного дашборда.

- Цены обновляются отдельной кнопкой по выбранным магазинам, без повторного импорта финансов. Ozon: `/v5/product/info/prices`; WB: `GET /api/v2/list/goods/filter` с пагинацией до пустой страницы. [Документация WB](https://dev.wildberries.ru/en/openapi/work-with-products).
- Для Ozon доступны черновики базовой, минимальной цены и цены до скидки; для WB — базовой цены и скидки продавца. Разные цены по размерам WB пока блокируют редактирование. Нулевая цена из API показывается как ноль и сопровождается предупреждением при подготовке новой цены.
- Массовые операции: процент, прибавление/вычитание рублей, фиксированная цена, наценка от заполненной себестоимости. Округление к ближайшему рублю, 10 или 100 рублям, либо до копеек.
- Перед сохранением сервер пересчитывает изменения, сверяет версии товара, валюту, минимальную цену, актуальность снимка (24 часа) и предупреждения. Повтор запроса не создаёт вторую заявку; один товар не может одновременно попасть в два открытых черновика/заявки на проверке.
- Заявки: черновик → на проверке → возврат с причиной или отмена. Подтверждение руководителя и отправка на площадки **ещё не реализованы**: текущие ключи предназначены для чтения, отдельной аутентификации сотрудников нет. Статусы используются для подготовки в общем локальном рабочем месте, а не как защищённое разграничение прав. Уведомления не отправляются.
- Заметки и метки «Проверить» / «К закупке» сохраняются локально. Каталог и заявки выгружаются в CSV с защитой от формул в текстовых ячейках.

Заявки, заметки и журнал хранятся в `.private/management.json`; цены WB — в `.private/prices-<id>.json`, цены Ozon вместе с себестоимостью — в `.private/costs-<id>.json`. В этих файлах нет новых API-ключей. Черновики не меняют импортированные цены и не вызывают методы записи площадок. Основной обзор продолжает учитывать все исторические финансовые операции.

Проверка: `node --test test/dashboard.test.cjs test/management.test.cjs`. Интерфейс сохранения заявки, передачи на проверку, возврата и заметок проверен отдельно на тестовом магазине; рабочие заявки не создавались.

# Обзор руководителя

На главной странице добавлены 16 виджетов по умолчанию, настройка их состава, сравнение с предыдущим периодом той же длины, график по дням, расшифровка расходов по услугам Ozon, сравнение магазинов и таблица начислений по SKU с поиском, сортировкой, CSV и переходом к управлению товаром. Дополнительно можно включить штрафы, товары без остатков и заполненность себестоимости. Настройки виджетов сохраняются в браузере.

По умолчанию выбран период «Сегодня»; рядом доступен «Вчера». Даты определяются по Москве и переходят на новый день при обновлении открытой страницы. Для периода, включающего сегодня, показаны время загрузки заказов и финансов, отметка о незавершённом дне и справочное значение предыдущего полного периода. Процент изменения и красная/зелёная оценка до завершения дня не выводятся. Для завершённых периодов сравнение работает как прежде.

Источники Ozon:

- `/v1/analytics/data`: сумма заказов и количество заказанных товаров по дням за 60 календарных дней. Это заказы, а не оплаченные продажи.
- `/v1/finance/accrual/types`: справочник названий услуг и начислений.
- `/v1/finance/accrual/by-day`: реализация, комиссия, логистика, рекламные списания и другие начисления за последние 30 календарных дней. Суммы сверяются с итогом каждой операции в копейках. Несопоставленные суммы и операции показываются отдельно. Справочник услуг сохраняет исходные названия Ozon; группы расходов определяет приложение.
- Остатки, цены и себестоимость берутся из существующего импорта товаров. Стоимость запасов рассчитывается только по заполненной себестоимости в рублях; это оценка текущего снимка, без сравнения с прошлым периодом.

Сумма начислений после удержаний **не является чистой прибылью**. Баллы за скидки и софинансирование показаны справочно и не прибавляются повторно к реализации. Расходы без SKU не распределяются произвольно между товарами. Отрицательная реализация не трактуется как количество возвратов. Когда снимок не покрывает выбранный или предыдущий период целиком, показатель отсутствует, а не подменяется нулём. Финансовая детализация в новом обзоре относится только к Ozon; при выборе WB доступны прежние показатели.

Работающий локальный сервер запускает импорт Ozon каждые 30 минут: заказы, справочник услуг, товары, себестоимость, остатки и финансовые начисления. Проверка расписания выполняется каждые 30 секунд и не зависит от открытой вкладки. Интервал считается от начала предыдущей попытки; параллельные повторы одного импорта блокируются. Расписание восстанавливается после перезапуска по сохранённым отметкам попыток. Если предыдущая загрузка ещё идёт, следующая ждёт её завершения. Кнопка «Обновить из Ozon» запускает загрузку вручную. Данные могут поступать из Ozon с задержкой. Отдельной службы Windows и автозапуска при включении компьютера нет: нужен работающий `node server.cjs`. Магазин «юСтальКрепеж регион» не подключён.

При выборе одного дня график показывает накопительный итог этого дня по времени фактической загрузки (Москва), а под ним — изменение между загрузками и последние восемь наблюдений. Для «Сегодня» по умолчанию показана сумма заказов; можно выбрать количество, реализацию, итог начислений или рекламу. Заказы и финансы имеют отдельные ряды по времени своих загрузок. Наблюдения сохраняются в `.private/intraday-<id>.json` на 32 дня; одинаковый снимок повторно не записывается. В первой точке используется уже имеющийся достоверный снимок. До него линия и нули не дорисовываются. Суммарная точка появляется только после нового наблюдения каждого выбранного магазина, с расхождением времени загрузок не более 30 минут. Ошибка одного магазина не превращается в нулевое значение. Изменение между снимками может включать корректировки Ozon и не является точным почасовым отчётом о времени оформления заказов.

Дополнительные снимки: `.private/insights-<id>.json` (заказы и справочник услуг), `.private/ledger-<id>.json` (восстанавливаемый кэш финансов). Ключи остаются в существующем хранилище DPAPI. Основное приложение: порт 4317; зеркало на порту 4318 обновляется отдельно.

Все 57 автоматических проверок проходят: расчёты и знаки начислений, отсутствие двойного счёта, неполные периоды, отрицательные операции, неизвестные услуги, фильтр архивных товаров, даты, существующие сценарии управления товарами, расписание на 30 минут, переход дня по Москве, сохранение истории, объединение магазинов, пропущенные обновления, ABC-анализ, сравнение дней и экономика по себестоимости. Фильтры, настройка виджетов, расшифровка расходов, график сегодняшних снимков, избранное и карточки SKU также проверены в браузере.

# Приоритеты и аналитика товаров

«Пульс бизнеса» показывает лидирующий магазин по реализации и число SKU группы A. Для одного дня дополнительно показано изменение суммы заказов между двумя последними загрузками; для нескольких дней — доля десяти ведущих SKU в положительной реализации. При неполном финансовом периоде выводы по общему набору магазинов не рассчитываются.

В приоритетах доступны четыре проверяемых правила с переходом в отфильтрованную таблицу: есть реализация при нулевом текущем остатке; нет положительной текущей себестоимости; отрицательные начисления по SKU; логистика не ниже 30% реализации. Первые два правила исключают архивные SKU и позиции без карточки в текущем каталоге. Неизвестный остаток не считается нулевым. Порог логистики — правило отбора для проверки, а не норматив. Отрицательные начисления не называются убытком. Количество указано в SKU, а не в уникальных карточках товара.

ABC рассчитывается по положительному итогу реализации каждого SKU за выбранный период: A до накопленного порога 80%, B до 95%, C — остаток. SKU, пересекающий границу, остаётся в текущей группе. Из-за этого фактические доли могут отличаться от 80/15/5. Нулевые и отрицательные итоги исключены из знаменателя и получают знак «—». Архивные SKU сохраняются в финансовой аналитике. Для текущего дня анализ предварительный и меняется с поступлением начислений.

Карточки магазинов показывают реализацию, долю в общем итоге и начисления/удержания на 100 рублей реализации. Если реализация ≤ 0 или снимок магазина неполон, соотношения не вычисляются. Начисления на 100 рублей не являются маржой или прибылью. Щелчок по магазину применяет общий фильтр; подробная денежная таблица раскрывается под карточками.

В таблице SKU добавлены группа ABC, доля, текущие остаток и себестоимость, отметки проверок, фильтры и сортировки. Щелчок по названию открывает подробности и переход к подготовке цен и заметок. Звёздочка добавляет SKU в избранное; выбор сохраняется только в этом браузере (`pult-favorite-skus-v1`) и не меняет данные Ozon. Избранное отображает позиции с начислениями в выбранном периоде. CSV содержит все строки с применёнными фильтрами, группу ABC, сигналы проверки и валюту себестоимости. Быстрые кнопки периода доступны над датами.

Описание полей: [Ozon Seller API](https://docs.ozon.ru/api/seller/).

## Магазины на графике

Флажки над графиком позволяют показывать общий итог всех подключённых магазинов Ozon, один магазин или несколько отдельных линий одновременно. «Все линии» включает общий итог и магазины; «Только общий» возвращает исходный вид. Выбор относится только к графику и сохраняется при переключении периода, показателя и автоматическом обновлении страницы данных. Общий итог не зависит от фильтра магазина в верхней части дашборда; остальные блоки продолжают использовать этот верхний фильтр.

Для каждого выбранного магазина загружается его собственный отчёт за те же даты. Для одного дня используются фактические внутридневные наблюдения, для нескольких — дневные значения. Линии имеют общую шкалу и разные цвета; под графиком указаны суммы и время последних точек. Пропущенные данные не превращаются в нули. Общая линия уже включает все магазины и не складывается с отдельными. По умолчанию оборот показан метрикой «Заказано на сумму»; «Реализация» выбирается отдельно. Финансовые показатели WB в этот график не входят.

## Тёмный интерфейс

Рабочий обзор, управление товарами и подключение магазинов используют общую тёмную палитру `dist/dark.css`. Оформлены карточки, таблицы, формы, окна деталей, состояния ошибок и проверки заявок. Цвета линий графика задаются переменными темы и совпадают с легендой; зелёные, красные и янтарные состояния сохранены. Тема действует по умолчанию, включая стандартные элементы выбора дат и списки браузера.

## Навигация и работа с графиком

Закреплённая верхняя панель на обзоре и странице управления товарами содержит «Найти раздел» (Ctrl+K, также Cmd+K) и переключатель компактных таблиц. Поиск находит разделы по названию и словам вроде «цены», «график», «остатки»; доступны клавиши стрелок, Enter и Escape. Он не отправляет запросы на внешние сервисы. Высота строк сохраняется в браузере и применяется к обеим страницам; заголовки длинных таблиц остаются видимыми при прокрутке.

На графике точку можно выбрать мышью, касанием или клавишами ←/→ после Tab; Home и End переходят к первой и последней доступной точке. Под графиком показаны магазин, фактическое время загрузки (МСК), значение и изменение к соседней предыдущей точке того же магазина. Для нескольких дней показано изменение к предыдущему дню. При пропуске предыдущего значения разница не вычисляется; нули и отрицательные корректировки сохраняются. Панель выбранной точки отделена от последних итогов линий.

## Сравнение сегодняшнего дня

Для периода «Сегодня» можно включать вчерашний день и тот же день недели семь дней назад. Сравнение работает для общего итога и каждой выбранной линии магазина. Накопительные снимки прошлых дней совмещаются по московскому времени. Разница и процент показываются только при наличии прошлого снимка не позднее сегодняшнего и с отставанием не больше 30 минут; при нулевой или отрицательной базе процент не рассчитывается.

Если история наблюдений за прошлый день ещё не накоплена, дашборд показывает его итог за весь день в отдельной карточке и горизонтальным пунктирным уровнем. Это справочный уровень полного дня, а не восстановленная почасовая линия. Изменение к сегодняшнему времени в таком случае не рассчитывается. История началась с подключения наблюдений и не восстанавливается из дневных итогов. Недоступные данные явно отмечены и не заменяются нулём.

## Прибыль и экономика Ozon

Раздел «Прибыль и экономика» рассчитывает управленческую оценку до налогов и внешних расходов за выбранный период. Основа — итог всех начислений Ozon после удержаний минус себестоимость реализованных единиц с учётом возвратов. Комиссия, логистика, реклама и другие удержания уже включены в начисления и повторно не вычитаются; баллы и софинансирование повторно не прибавляются. Суммы считаются в копейках. Финансовые данные WB в этот расчёт не входят.

В текущем API начислений нет отдельного количества. По [описанию Ozon](https://docs.ozon.ru/api/seller/#operation/GetFinanceAccrualByDay), `sale_amount` — сумма реализации, `seller_price` — цена за единицу. Количество для оценки определяется только при точном целочисленном делении первой суммы на вторую в копейках. Неоднозначные отношения не округляются: такие строки требуют проверки. Возвраты уменьшают количество и восстанавливают себестоимость; повреждения, списания и фактическая история закупочных цен не известны.

Себестоимость берётся из текущего снимка Ozon, привязанного к товару и его SKU внутри конкретного магазина. Нулевые, неизвестные, неоднозначные и нерублёвые значения не принимаются за достоверную себестоимость. Архивный товар продолжает участвовать в историческом финансовом расчёте. Кэш финансов версии 3 автоматически перестраивается из сохранённого исходного снимка и содержит расчётные проданные и возвращённые единицы.

Результат по SKU включает только связанные с ним начисления. Общие начисления и удержания магазина входят в полный итог магазина один раз и не распределяются произвольно по товарам. При неполных количествах, себестоимости или финансовом периоде полный результат остаётся недоступен. Вместо него отдельно показаны результат рассчитанных SKU **до общих расходов магазина**, учтённая часть себестоимости и причины неполноты. Маржинальность считается только при положительной реализации; результат на единицу — при положительном количестве за вычетом возвратов.

В таблице экономики доступны поиск, отбор отрицательного и положительного результата, список SKU с недостающими данными, сортировка и переход к карточке управления товаром. Налоги, зарплаты, аренда, упаковка и другие внешние расходы пока не внесены. Поэтому показатель не называется бухгалтерской чистой прибылью. Данные текущего дня предварительные и обновляются вместе с существующим импортом каждые 30 минут.
