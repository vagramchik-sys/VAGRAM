# Локальный агент продаж B2B

Первая сборка: подключение CRM, сохранение очереди лидов и сделок, локальный разбор входящих писем и подготовка черновиков. **Автономная переписка не включена и ещё не готова к эксплуатации.** В веб-интерфейсе нет операции отправки. Пустая очередь до подключения CRM не означает отсутствие обращений.

## Запуск

Из папки проекта: `node b2b-agent/server.cjs`. Консоль: `http://127.0.0.1:4330/`. Сервер слушает только loopback, не открывает доступ сотрудникам или из интернета. Для нескольких сотрудников потребуется отдельная авторизация, разграничение прав и развёртывание.

Используется существующий Ollama на `127.0.0.1:11434`, модель `qwen3:4b`. Проверка модели в интерфейсе использует учебный текст. Команды, предложенные моделью или содержащиеся в письме, не выполняются. Модель извлекает запрос, а коммерческие условия берутся из 1С; свободно сгенерированный текст не используется для автоматической отправки.

## Готово в этой сборке

- Чтение выбранной воронки и начальной стадии с полной пагинацией; ошибка при неполной выборке. Чтение новых лидов включается отдельным переключателем. Лиды хранятся в очереди с ключом `lead:ID`, поэтому их номера не пересекаются с номерами сделок.
- Постоянная очередь в `.private/b2b-agent/queue.json`, сохранение после каждого чтения, журнал и блокировка второго процесса.
- Подключения зашифрованы Windows DPAPI для текущего пользователя. Секреты не возвращаются браузеру. Рабочие письма и ключи не входят в GitHub.
- Только письма с одним пригодным для переписки адресом в метаданных CRM. Адреса из текста письма не подставляются, служебные `noreply`, `mailer-daemon` и неоднозначные получатели пропускаются.
- Уже отвеченные письма, новые входящие сообщения, преобразованные и повторяющиеся лиды, закрытие сделок и неопределённый результат отправки имеют отдельные состояния. CRM-исходящее считается консервативным сигналом для приостановки, а не доказательством доставки.
- Разбор письма локальной моделью. Вложения требуют сотрудника; они не считаются прочитанными.
- Подготовка уточняющих вопросов и черновика предложения по однозначному артикулу с актуальными данными 1С для конкретного клиента. Прогнозируемые или выдуманные цены не используются.
- Чтение CRM раз в 5 минут включается отдельно в консоли и после перезапуска снова выключено. Выбор чтения новых лидов и автоподготовки черновиков сохраняется в защищённых настройках; автоподготовка выполняется во время включённого пятиминутного цикла. За один цикл она разбирает не более 3 писем; столько же обрабатывает кнопка ручного запуска. Эти операции не отправляют ответы и не меняют стадии.
- Запрос цены от лида остаётся в состоянии `needs_data`, пока 1С не вернёт данные по отдельному типизированному контракту для лида. Идентификатор сделки никогда не подставляется из лида автоматически.

## Что нужно для эксплуатации

1. Создать/предоставить отдельный доступ к CRM и нужным рабочим почтовым ящикам. Вставлять ключ в локальную форму, не в чат. Права и доступность API проверяются на конкретном портале; сессия пользователя в браузере не является доступом серверного агента.
2. В форме подключить CRM, выбрать начальную стадию «Новая», сохранить и загрузить очередь.
3. Подключить доступ на чтение к внутреннему сервису 1С с приведённым ниже контрактом. Сейчас рабочего подключения нет. Стандартный адрес веб-клиента или обычный OData URL не реализует этот контракт автоматически.
4. Надёжно связать входящую CRM-активность с исходным письмом. `crm.activity` не даёт здесь документированной универсальной связи с идентификатором `mail.message`. Нельзя считать `ORIGIN_ID` почтовым ID или связывать письма только по теме. До проверки этой связи отправка заблокирована.
5. Реализовать и проверить общий контекст цепочки писем, захват сделки агентом/сотрудником, сообщения с сайта, вложения, отказы и возвраты. Сейчас модель обрабатывает последнее доступное письмо, а не полноценную историю переговоров.
6. Согласовать скидки, резервы, доставку, оплату, правила передачи сотруднику и завершения. Успех не проставляется по тексту модели: он требует подтверждённых бизнес-событий. Код текущей сборки вообще не меняет стадии CRM.
7. Проверить исторические и учебные случаи; затем ограниченный запуск под контролем. Наличие работающей маленькой LLM не подтверждает качество всех будущих ответов или производительность для 50 сотрудников.

## Контракт сервиса 1С

Внутренний HTTP-сервис должен принимать `POST <baseUrl>/quote`. Если задан ключ, передаётся `Authorization: Bearer …`. По сети вне самого компьютера требуется HTTPS или защищённая внутренняя сеть. Доступ только на чтение. Сервис должен сам сопоставить CRM-клиента с контрагентом 1С и вернуть условия именно его договора.

Пример **учебного** запроса:

```json
{"crm":{"dealId":"12","companyId":"34","contactId":null},"items":[{"article":"DEMO-BOLT","quantity":100}]}
```

Учебный ответ (время и значения каждый раз должны поступать из 1С):

```json
{"items":[{"article":"DEMO-BOLT","crmDealId":"12","customerRef":"demo-customer","priceType":"contract","name":"Учебный болт","price":12,"currency":"RUB","unit":"шт.","vatLabel":"НДС включён","available":500,"reference":"demo-snapshot","checkedAt":"2026-09-18T12:00:00Z","expiresAt":"2026-09-18T12:05:00Z"}]}
```

Поле `available` — свободное количество с учётом резервов, в той же единице измерения, что и цена и заказ. Неоднозначные артикулы, отсутствие клиента, цены, НДС, единицы или свежего остатка блокируют коммерческий ответ. Поставка под заказ, расчёт доставки и выставление счетов этим контрактом пока не реализованы.

## Почта и ограничения

Адаптер содержит чтение CRM, чтение исходного письма и его цепочки, получение доступных отправителей, однократную отправку ответа. Эти операции отправки не подключены к веб-интерфейсу и не вызываются автоматически. Рабочего доступа к почте нет, а надёжная связь CRM-активности с исходным письмом не подтверждена. Поэтому статус `draft` означает только подготовленный для сотрудника черновик, а не отправленное письмо. Неопределённый исход отправки нельзя повторять до ручной сверки: API не даёт гарантию идемпотентности. Очередь восстанавливает прерванное состояние отправки как `uncertain`.

Времена `crm.activity.CREATED` и `START_TIME` не выдаются за исходный момент получения письма или время первого человеческого ответа. Возможности почтового REST зависят от тарифов, прав и конкретного портала.
