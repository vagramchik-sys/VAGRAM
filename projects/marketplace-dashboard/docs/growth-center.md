# Центр роста

`/growth.html` объединяет цену, подтверждённую себестоимость, остаток, финансовый результат, рекламу и выбранных конкурентов товара. Данные собственных товаров читает существующий PostgreSQL optimizer; открытие списка не вызывает внешние API.

## Расчёты

Фактическая экономика использует завершённый финансовый период и реализованные единицы SKU. Расход и заказы Performance не подмешиваются к финансовым удержаниям. Сценарии показывают условные пороги объёма, а не прогноз спроса или гарантии позиции.

Плановые условия хранятся приватно в PostgreSQL, документ `growth-settings/terms`. Проценты задаются от цены продавца и применяются ко всем товарам. Плановый вклад равен цене после резервов комиссии и рекламы минус подтверждённая себестоимость и прочие расходы на реализованную единицу. Фактические комиссия и реклама повторно не вычитаются. Исторические прочие расходы предполагаются неизменными. При отсутствии полного свежего финансового основания вклад и минимальная цена неизвестны.

## Конкуренты

`growth-watchlist/{store}-{product}` хранит выбранные карточки Ozon. Кандидат и подтверждённый аналог различаются; для подтверждения нужны характеристики/пояснение и размер упаковки. Показатели из аналитики Ozon относятся к указанному периоду. Средняя и минимальная историческая цена не используются как текущая цена покупателя.

`growth-evidence/{store}-{product}` хранит до 30 ручных наблюдений текущих цен: регион, запрос, время, количество единиц, цена покупателя и необязательная позиция. Для расчётного сравнения нужны сопоставимые аналоги и наблюдение не старше суток. Это выбранная выборка, а не мониторинг всех продавцов.

Индекс цены можно прочитать отдельной кнопкой через `/v5/product/info/prices`. Это агрегированный ориентир Ozon без списка конкурентов. Внешнее чтение использует ограниченную очередь и не занимает очередь локальных отчётов.

## API и ограничения

- `GET /api/growth`: магазин, поиск, завершённый период до 90 дней, пагинация, выбранная цель.
- `GET/POST /api/growth/terms`: приватные плановые условия.
- `GET/POST /api/growth/watchlist`: привязки по магазину и товару.
- `GET/POST /api/growth/evidence`: ручные рыночные наблюдения.
- `GET /api/growth/market`: чтение агрегированного индекса Ozon.

Все маршруты используют общую авторизацию владельца. Запись требует UUID команды и ожидаемой версии. Повтор команды возвращает сохранённый результат, несовпадение версии требует обновления. URL конкурента ограничен HTTPS-карточками `ozon.ru/product/`. Чувствительные значения и индивидуальные условия не входят в исходный код.

## Обновление и применение

Кнопка обновления ставит в существующую очередь загрузку каталога, остатков, цен и 30-дневных финансов выбранного магазина. Реклама добавляется при подключённом Performance API. Это загрузка источников магазина; она не является точечным запросом только выбранного SKU. Статус показывает задания и причины неполноты экономики. Успешная постановка в очередь ещё не означает, что данные получены. Открытие списка по-прежнему не вызывает внешние API.

Отчёт «Товары на Ozon» можно импортировать в формате XLSX, CSV или TSV (до 8 МБ). Предпросмотр распознаёт ссылки, названия, продавцов, бренд и исторические показатели. Пользователь выбирает карточки; подтверждённые сопоставления и упаковки сохраняются. Для импорта метрик нужно явно подтвердить даты периода. Неоднозначная дата формирования не используется для угадывания периода. Собственный SKU исключается. XLSX извлекается локальным Python без выполнения формул, с ограничением размера архива и числа строк. Этот импорт не подключает непрерывный мониторинг Ozon.

Цена продавца изменяется только по явно выбранной сумме, после предпросмотра и отдельного подтверждения. Перед отправкой цена повторно читается из Ozon, команда и блокировка SKU сохраняются в PostgreSQL. Переотправка с тем же UUID возвращает результат. Неопределённый исход блокирует повторную запись до сверки; сверка только читает Ozon и не приписывает приложению чужое изменение. Новый транспорт записи цены отделён от фонового read-only транспорта PostgreSQL.

Бюджет и состояние рекламы используют уже существующий контроллер кампаний. Изменение бюджета касается всей кампании, включая другие товары; это явно показано в предпросмотре. Требуется подтверждение отсутствия другого управляющего сервиса. Изменение ставок остаётся отключено из-за неподтверждённых единиц и влияния метода Ozon на стоп-слова. Расписание доступно в отдельном модуле управления рекламой с его собственным подтверждением.

Новые маршруты: `GET/POST /api/growth/refresh`, `POST /api/growth/import/preview`, `POST /api/growth/price/preview`, `POST /api/growth/price/apply`, `GET /api/growth/price/status`, `POST /api/growth/price/reconcile`, `POST /api/growth/ad/preview`, `POST /api/growth/ad/apply`, `POST /api/growth/ad/reconcile`. Все требуют авторизации владельца; POST дополнительно проходит общую проверку Origin. Предпросмотр цены живёт две минуты; неопределённый исход сверяется после защитного интервала, без автоматического повтора записи.

Рекомендация и сценарии используют одну базу — индивидуальные плановые условия. Фактическая экономика остаётся отдельной. При частичных данных известный остаток до прочих затрат не называется прибылью. Ценовой сценарий показывает условный порог изменения объёма, а не прогноз спроса. Для целей объёма/позиции требуется дополнительное наблюдение эффекта; переключение цели не создаёт доказательств.

## Проверка

Прерванные задания чтения каталога (`market`) и рекламы (`ozon-performance`) восстанавливаются только после доказанного завершения прежнего локального процесса либо фактически завершённого вызова в текущем процессе. Затем блокировки публикации дожидаются окончания возможной SQL-записи, и проверяется квитанция исходной команды. Живой или неизвестный исполнитель не сбрасывается. Повтор чтения использует ту же команду и допускается только при доказанном отсутствии записи и неизменной версии источника.

Для реализованных единиц используется явно переданное положительное целое `quantity` в финансовом ответе Ozon. Поле подтверждено наблюдаемыми ответами, но не рассматривается как официально документированная гарантия API. Некорректное явное значение оставляет количество неизвестным; только при отсутствии поля сохраняется прежний расчёт по отношению суммы к цене.

Тесты `growth-advisor`, `postgres-growth`, `growth-watchlist`, `growth-ui` проверяют условную арифметику, неизвестные/устаревшие основания, локальную запись, идемпотентность, область магазина, URL и интерфейс. `ozon-ad-control-http` проверяет независимость локальных отчётов от медленных внешних чтений.
