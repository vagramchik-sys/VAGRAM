# Общая система АТЛАС и Пульт: контракт backend

Статус: проект интеграции. Общий вход, единая оболочка и доступ с других устройств ещё не запущены. Переход по ссылке или iframe не считается завершением объединения.

АТЛАС отвечает за общую оболочку, личные учётные записи, сессии и назначение прав. Пульт сохраняет существующие backend-модули, рабочие данные и импорты. Hosted frontend обращается к общему серверу; localhost пользователя не считается доступным удалённому устройству.

## Личность и граница доверия

После серверной проверки общей сессии адаптер получает `{userId, role, partnerId?}`. Роль относится именно к Пульту: `owner` либо `partner`. Права администратора другого модуля сами по себе не дают owner-доступ Пульта. Связь пользователя с партнёром хранится на сервере; клиент не выбирает чужой partnerId или набор товаров.

Возможные механизмы проверки: серверная валидация общей сессии или короткоживущее подписанное утверждение с проверкой issuer, audience для Пульта, срока действия и отзыва. Точный механизм согласуется с ведущим backend АТЛАС. Прямым заголовкам X-Role/X-User-Id доверять нельзя; внешний прокси обязан их удалять. Между хостами нужен аутентифицированный защищённый канал.

Проверка личности должна предшествовать маршрутизации и выдаче owner-сессии. Текущий локальный сервер автоматически выдаёт owner-cookie при открытии HTML, поэтому его нельзя просто открыть через внешний прокси. Общий режим должен отказывать по умолчанию. Host/Origin и доверенные forwarded-заголовки задаются явно; произвольные origin не разрешаются.

## Разделение API

| Область | Доступ | Существующий backend |
| --- | --- | --- |
| Реестр идей | owner | `/api/ideas`, `/api/ideas/create`, `/api/ideas/update` |
| Закупки | owner | `/api/procurement` и parse/request/import/compare |
| Настройка партнёров | owner | `/api/partners/state`, save, issue-credential, revoke-credential |
| Благотворительность компании | owner | `/api/charity`, `/api/charity/import` |
| Магазины, товары, финансы и подключения | owner | Существующие маршруты основного сервера |
| Кабинет партнёра | partner | `snapshotForPartner(partnerId)` через отдельный адаптер общей identity |

`snapshotForPartner` повторно проверяет активность партнёра и явно назначенные productKeys. Проекция исключает внутренние ставки, маржу, ключи, чужие товары, общую благотворительность и owner API. Полный owner-объект не отправляется на клиент для последующего скрытия полей. Деактивация пользователя в АТЛАС и деактивация партнёра в Пульте прекращают доступ.

Локальные коды и credentialVersion партнёрского listener не заменяют общую identity АТЛАС. Для неё нужен отдельный валидатор, сохраняющий проверки активности и назначений. Необходимы тесты подмены identity, истёкшей и отозванной сессии, чужого partnerId и доступа партнёра к owner API.

## Хранение и перенос

Единственный источник рабочих данных — существующая `.private` Пульта. АТЛАС хранит общие учётные записи и связь с партнёром, обращается к бизнес-данным через backend. Не создавать параллельные каталоги, ledger, реестр идей или копии пожертвований. Фоновые импорты выполняются в одном экземпляре.

Ключи магазинов защищены Windows DPAPI CurrentUser. Копирование файлов на другой сервер не гарантирует расшифровку. При переносе нужен контролируемый доступ в целевом контексте либо повторное подключение магазинов; ключи не проходят через frontend или публичный репозиторий.

Порядок миграции: согласовать хост и auth-контракт; сделать приватную резервную копию и инвентаризацию данных; проверить целевой доступ к ключам; остановить запись на время переноса; перенести единый источник данных; проверить количество записей, версии и контрольные суммы; переключить только после проверки входа и разграничения доступа. Старый источник сохраняется для восстановления и не продолжает независимую запись.

## Следующее решение ведущей задачи

Нужны способ серверной проверки сессии, назначение Pult-ролей, отзыв доступа, целевой origin и расположение защищённого backend-канала. До согласования не открывать локальный owner-listener наружу и не объявлять доступ с других устройств готовым.
