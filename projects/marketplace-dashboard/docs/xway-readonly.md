# XWAY в Пульте

`/xway.html` — информационная страница с проверенными наблюдениями из кабинета XWAY. Показывает подключение и тариф, товары, настройки и просмотренные кампании. Каждая запись содержит источник и время проверки. Количество просмотренных кампаний отделено от общего количества в кабинете; архивные и непросмотренные записи могут отсутствовать.

Это не автоматическая синхронизация. Публичный API рекламного XWAY AI для этой интеграции не подтверждён. XWAY Seller API — отдельный продукт. Пульт не отправляет запросы к XWAY, не меняет кампании, ставки, бюджеты, правила, настройки или токены. HTTP-маршрут `GET /api/xway` возвращает только локально сохранённые наблюдения; остальные методы запрещены. Доступ защищён общей локальной сессией Пульта.

## Данные и обслуживание

В `pult_xway.accounts`, `settings`, `campaigns` хранится отдельная строка на кабинет, настройку или кампанию. Полные DOM, страницы, ответы кабинета и секреты не сохраняются. Runtime `pult_app` имеет только `SELECT`. Схему создаёт локальный migrator; импорт выполняется отдельно через CLI, в транзакции с общей блокировкой резервного копирования. Старые наблюдения не перезаписывают более свежие. Отсутствие записи во входном файле не удаляет ранее проверенные сведения.

Опциональная таблица `pult_xway.products` содержит только проверенные товарные наблюдения для сигналов: кабинет и ключ товара, название, SKU/артикул, текущий остаток, заказанные единицы и выручку, а также рекламные показы, клики, корзины, заказы, выручку, расход, ДРР, общий ДРР, CTR и конверсию клика в заказ. Часть полей, включая границы периода, может быть `null`; неизвестное не считается нулём. Источник и время проверки обязательны для происхождения факта. Эти строки используются только для просмотра и не запускают поставки или изменения рекламы.

Приватный файл: `{version:1, accounts:[], settings:[], campaigns:[]}`. Поля определены в `storage/postgres-xway.cjs`; непредусмотренные поля отклоняются. На каждой записи обязательны `sourceUrl` (HTTPS-адрес am.xway.ru без query и fragment) и `observedAt` (ISO с часовым поясом). Настройки и кампании ссылаются на `accountKey`. Неизвестные метрики — `null`, а не ноль. Суммы передаются в рублях, проценты — как отображаемое число процентов, не дробь. При нуле заказов нулевой ДРР преобразуется в `null`. ДРР не показывает прибыль или убыток.

```powershell
node scripts/xway-observations.cjs validate work/sql-operations/xway-observations.private.json
node scripts/xway-observations.cjs schema
node scripts/xway-observations.cjs import work/sql-operations/xway-observations.private.json
node scripts/test-pult-postgres.cjs --suite xway
```

`schema` и `import` используют защищённый `.private/postgres-setup/migrator.dpapi`; `validate` не подключается к базе. CLI выводит только количества записей и безопасные коды ошибок. Личные идентификаторы, имена кампаний, суммы и проверенные факты остаются в SQL и приватном файле, вне Git. Runtime не нужно перезапускать для изменения наблюдений.

## Подтверждённая механика

На [Ozon](https://xway.ru/ozon) XWAY описывает управление продвижением товара: необходимые кампании, ставки, лимиты расходов, дневной бюджет и распределение средств между кампаниями. Это возможности сервиса, а не подтверждение включённой автоматизации у каждой кампании.

На [Wildberries](https://xway.ru/wb) заявлены управление ставками, кластерами и временем показов, поиск фраз и отслеживание позиций. Конкретные возможности зависят от площадки и тарифа.

## Сигналы «Требует внимания»

Страница локально вычисляет подсказки по уже сохранённым наблюдениям и не меняет рекламу. Неизвестные значения не считаются нулём. Проблемный сигнал при большом числе кликов и нуле рекламных заказов предлагает проверить атрибуцию и карточку, но не объявляет расход бесполезным. Оценка малого остатка использует текущий остаток и темп заказанных единиц завершённого периода; это оценка, не прогноз.

Кандидат на рост появляется только для кампании с достаточной выборкой, свежим завершённым периодом и ДРР заметно ниже медианы не менее пяти других кампаний того же кабинета, периода и типа. Та же группа сравнения помогает отметить необычно высокий ДРР, но только как относительный ориентир кабинета, а не порог прибыльности. Поиск, статус и стратегия определяют видимые карточки, но не меняют группу сравнения. Это повод проверить настройки, маржу и остаток, а не команда менять бюджет. Число или диапазон, похожий на целевой ДРР в названии кампании, подписывается как ориентир в названии и не считается подтверждённой настройкой. Товарные сигналы учитывают магазин и поиск.

[База знаний XWAY](https://xway-docs.teamly.ru/at/9872c3e8-78c4-4b45-a13f-96b05bafab4c) доступна по ссылке из кабинета. Определения и периоды метрик необходимо сверять с источником; страница не пересчитывает атрибуцию заказов самостоятельно.
