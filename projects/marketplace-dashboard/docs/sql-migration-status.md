# Пульт: API и записи PostgreSQL

Актуальная рабочая архитектура: marketplace API → отдельные записи PostgreSQL → экраны и отчёты Пульта. HTTP-запросы к Ozon/WB выполняет сервер Node.js с существующими защищёнными подключениями. Прямые HTTPS-запросы из PostgreSQL пока не реализованы.

## Хранение и обновления

- `pult_live.facts` содержит отдельные товары, остатки, операции, строки заказов и аналитики. Ключ записи включает магазин, домен, тип сущности и бизнес-ключ; отдельные индексы поддерживают дату и исходный порядок.
- `pult_live.heads` хранит только небольшие метаданные, ревизию и контрольные суммы. Полного исходного документа в нём нет.
- Публикация заменяет только явно переданные разделы в одной транзакции. Входные строки поступают ограниченными пакетами; служебные строки удаляются перед commit. Ошибка позднего пакета откатывает всю публикацию.
- `record_journal` сохраняет изменения отдельных записей. `commands` хранит неизменяемые подтверждения команд; повтор команды не применяет её заново. Проверка ожидаемой ревизии защищает от перезаписи более новых данных.
- Очередь обновления хранит каждое задание отдельно. Задания производной аналитики передают ссылки на версии источников, а не полные копии данных. Состояние очереди читается без загрузки тяжёлых параметров.
- История получает нормализованные факты и сведения о покрытии. Текущий сбор больше не создаёт полные архивы источников.
- Совместимые адаптеры при необходимости собирают объект в памяти из строк SQL. Названия некоторых прежних функций и API-полей сохранены для интерфейса; они не означают хранение полного снимка.

Небольшие бизнес-реестры, договоры и настройки продолжают использовать свои SQL-репозитории. Этот этап не объявляет все домены полностью нормализованными. Старые документы и архивы сохранены приватно для восстановления; текущие marketplace-чтения не используют их как резервный источник.

## Сводки и отчёты

Сводки читают нужные коллекции и скалярные поля финансовых операций. Производные отчёты получают ограниченные проекции источников с привязкой к ревизии. Финансовый ledger пересчитывается после подтверждённого обновления API и проверяется по ревизии, полному хешу рынка, типам начислений и периоду.

При восстановлении ledger финансовые операции читаются порциями из SQL. Недоступные значения себестоимости и прибыли остаются `null`. Отсутствие свежего источника не заменяется нулевым значением или старым архивом.

Ограниченные очереди чтения отделяют лёгкие сводки от тяжёлых отчётов. Ускорение конкретного экрана подтверждается отдельным замером; сам переход на SQL не является доказательством скорости каждого запроса.

## Перенос и восстановление

Миграция проверяет контрольную сумму каждого прежнего источника, преобразует его в строки и сверяет восстановленное содержимое. Повторный запуск использует проверенные checkpoints только при совпадении текущей ревизии и полного хеша; более новые API-изменения не перезаписываются. Финальная сверка выполняется после остановки прежнего writer.

Перед переносом очереди незавершённые попытки разрешаются по подтверждениям команд и ревизиям источников. Успех не выставляется без подтверждения. Задания, которые не были исполнены, получают явный результат перехода и затем могут быть созданы заново штатным расписанием.

Backup включает фактически существующие схемы, в том числе `pult_live`, под общей блокировкой записи. Manifest содержит их список; старые backup остаются совместимыми. Восстановление в отдельной базе сверяет данные, ограничения и индексы. Протоколы фактического переноса, сверки и восстановления хранятся только локально. Проверка синтетического backup не подменяет проверку резервной копии рабочих данных.

## Запуск и проверка

```powershell
node --max-old-space-size=8192 scripts/start-pult-postgres.cjs --check
node --max-old-space-size=8192 scripts/start-pult-postgres.cjs
```

Основной локальный адрес — `http://127.0.0.1:4317/`, партнёрский порт — 4319. Режим `--check` проверяет готовность без запуска фоновых задач. PostgreSQL запускается отдельно. Bootstrap остаётся защищённым Windows DPAPI; приложение использует ограниченную роль без владения схемами и прав изменения журнала.

Изолированные PostgreSQL-тесты запускаются через `scripts/test-pult-postgres.cjs --suite NAME`. Suites `live-repository`, `live-sources`, `live-state-store`, `live-market`, `live-ledger-refresh`, `live-scheduler`, `live-history-capture`, `live-migration`, `application`, `backup` проверяют атомарность, повтор команд, права, историю, импорт и HTTP. Перед публикацией проверяется точная публикуемая версия командой `node scripts/check.cjs` общего репозитория VAGRAM.

Секреты, рабочие базы, прежние снимки, журналы и протоколы в GitHub не отправляются.
