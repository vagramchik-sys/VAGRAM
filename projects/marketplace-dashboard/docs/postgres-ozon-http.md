# Ozon HTTPS из PostgreSQL

Рабочий путь: планировщик Node → ограниченная SQL-функция → HTTPS Ozon → существующие обработчики → обычные строки `pult_live`. Чтение страниц использует отдельный SQL-пул. Накопленные данные и журнал команд сохраняются; новые архивы полных снимков этим транспортом не создаются. Название `SnapshotCollector` осталось у сборщика совместимого объекта в памяти, а не у способа хранения.

PostgreSQL backend самостоятельно открывает TCP/TLS-соединение. Node не пересылает HTTP и не расшифровывает ключ Ozon при фоновой загрузке. При подключении нового магазина Node защищает введённый ключ DPAPI и передаёт функции только шифротекст. WB и TrueStats используют прежние транспорты.

## Установка

Требуются Windows x64, существующая PostgreSQL 18.6 с `plpython3.dll`, запуск под Windows-пользователем, защитившим ключи DPAPI, и уже настроенные ограниченная роль `pult_app` и администратор `pult_admin`.

1. `powershell.exe -NoProfile -File scripts/install-pult-pg-python.ps1` устанавливает официальный CPython 3.13.15 рядом с PostgreSQL. SHA-256 архива и подпись DLL проверяются. `python313._pth` разрешает только каталог runtime и его стандартную библиотеку; системный PATH не меняется.
2. `node --test test/postgres-ozon-http.test.cjs` проверяет адаптер и Python. При пропущенной Python-проверке надо явно задать `PULT_PYTHON` на установленный `python.exe` и повторить её.
3. `node scripts/install-pult-ozon-http.cjs` читает существующий закрытый DPAPI bootstrap администратора, устанавливает `plpython3u` и две функции. Тело Python встраивается в SQL; рабочая папка приложения не импортируется PostgreSQL при запросе.
4. `node scripts/start-pult-postgres.cjs --check` проверяет состав приложения и права транспорта без запуска слушателей и API-запросов.
5. После корректного завершения старого runtime запустить `npm run start:postgres`. При незавершённых заданиях сначала разрешить их по сохранённым квитанциям команд, сохраняя CAS и идентификаторы операций. Одновременно запускать два runtime нельзя.

Перезапуск PostgreSQL для этой установки не требуется: новые backend-процессы загружают библиотеку. Работающая версия приложения переключается отдельным перезапуском Node после проверок.

## Ограничения и отказы

- Только `api-seller.ozon.ru:443`, проверка сертификата и имени узла, TLS не ниже 1.2, запрет перенаправлений и неглобальных IP. Произвольный URL недоступен.
- Разрешены десять используемых методов чтения. Изменение цен, товаров и остатков не разрешено.
- Владелец функций — администратор. `PUBLIC` не имеет EXECUTE; `pult_app` имеет только USAGE и EXECUTE этих функций, без CREATE схем, баз и PL/Python-функций. Search path фиксирован.
- SHA-256 содержимого реестра проверяется до DPAPI. API-ключ не включается в SQL-параметры, ошибки или журналы транспорта. Сообщения Ozon об ошибках не передаются вызывающему коду.
- Отдельный пул `pult_ozon_http` ограничен двумя соединениями. Пул интерфейса `pult_ui` сохраняет собственную ёмкость. Deadline запроса с повторами — 120 секунд, SQL statement timeout — 125 секунд; запрос ограничен 1 МиБ, ответ — 32 МиБ.
- Только подтверждённые HTTP 429/5xx могут повторяться в пределах deadline; `Retry-After` учитывается. Неопределённый исход SQL/сети автоматически не повторяется. Для аналитики 429 передаётся планировщику с периодом ожидания.
- Ошибка подключения магазина не сохраняет его ключ. Пустой или ошибочный ответ не подменяется демонстрационными данными.

## Восстановление и откат

Обычная резервная копия Пульта сохраняет рабочие SQL-данные. Схема `pult_ozon_http` содержит только версионированный код и права; она не входит в архив бизнес-данных. На восстановленном экземпляре надо отдельно установить проверенный Python и повторно выполнить установщик функций из той же версии исходников. До этого проверка готовности приложения завершается отказом. DPAPI требует исходную Windows-учётную запись и её ключи; исходники не заменяют их резервную копию.

При проблеме нового транспорта остановить новые задания и корректно завершить runtime. Не удалять таблицы или журналы команд. Администратор может отозвать EXECUTE у `pult_app` на `pult_ozon_http.request(text,text,jsonb,integer)` и `pult_ozon_http.verify_connection(text,text,integer)`; SQL-проверка готовности после этого блокирует новый запуск. Для возврата предыдущего поведения восстановить согласованную предыдущую версию исходников целиком и запустить её обычной командой. Автоматического перехода на Node HTTP в текущей версии нет. DLL не удалять, пока PostgreSQL использует её; расширение и функции можно оставить без разрешения EXECUTE.

## Проверка результата

Кроме тестов, при переключении выполняются авторизованный метод чтения Ozon, сопоставление `pg_backend_pid()` с TCP-соединением Windows на порт 443, запрет записи и создания PL/Python от прикладной роли, проверка нового подключения, независимость пула интерфейса, повторные обновления SQL-строк и HTTP-проверки отчётов. Результаты с локальными идентификаторами хранятся в закрытых рабочих файлах, не в GitHub.

Официальные источники: [PL/Python PostgreSQL 18](https://www.postgresql.org/docs/18/plpython.html), [встраиваемый Python для Windows](https://docs.python.org/3.13/using/windows.html#the-embeddable-package), [Python 3.13.15](https://www.python.org/downloads/release/python-31315/).
