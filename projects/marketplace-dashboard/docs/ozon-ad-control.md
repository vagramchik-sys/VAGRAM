# Управление рекламой Ozon в Пульте

Экран `/ad-control.html` использует напрямую Ozon Performance API и существующее
защищённое подключение магазина. Он не синхронизирует настройки через XWAY.

## Первая версия

- Чтение актуальных кампаний и товаров выбранного магазина.
- Изменение существующего недельного бюджета CPC-кампании товаров.
- Ручная остановка и запуск кампании в поддерживаемом состоянии.
- Одно временное окно в выбранные дни недели, часовой пояс Москва.
- Предварительный просмотр конкретного изменения, журнал, сверка результата.

Перед управлением кампанией пользователь подтверждает, что для неё выключено
управление в XWAY и других сервисах. В Пульте расписания по умолчанию выключены.
Открытие страницы и просмотр кампаний не изменяют рекламу.

Расписание выполняется только пока работает сервер Пульта и есть доступ к Ozon.
Проверка происходит раз в минуту; это не гарантия остановки в точную секунду.
После остановки сервера или потери связи действует последнее состояние Ozon.
Для финансового ограничения следует использовать недельный бюджет Ozon.

Планировщик включает обратно только кампанию, которую сам успешно остановил и
для которой подтвердил состояние `CAMPAIGN_STATE_INACTIVE`. Он не запускает
кампании с недостаточным бюджетом (`STOPPED`), архивные, завершённые,
запланированные на будущее или проходящие модерацию. Исходно выключенная
кампания сама не запускается. При изменении отметки обновления Ozon после
нашей остановки автоматическое возобновление блокируется.

## Ставки пока заблокированы

Официальная документация `PUT /api/client/campaign/{campaignId}/products`
предупреждает об удалении прежних стоп-слов и фраз со ставками. В описанной схеме
нет полей для их сохранения. Кроме того, карточки методов текущей, конкурентной
и обновляемой ставки не определяют масштаб строкового `uint64`.

Поэтому интерфейс и сервер запрещают запись ставок. Неизвестная единица не
превращается автоматически в рубли. Для продолжения требуется отдельная
изолированная тестовая кампания и проверка единиц и сохранности настроек.
Не включать запись только изменением флага в интерфейсе.

## Надёжность

Предпросмотр живёт две минуты. Перед применением сервер перечитывает кампанию
и сравнивает её состояние с просмотренным. Каждая команда имеет постоянный
UUID, а перед внешним запросом её намерение записывается в PostgreSQL.
После успешного HTTP-ответа значение снова читается из Ozon.

Таймаут, обрыв связи или неопределённый ответ блокирует дальнейшие изменения
этой кампании до сверки. Повторный запрос с тем же UUID не отправляет изменение
в Ozon заново. Не следует создавать новый UUID, чтобы обойти неизвестный исход.
После неопределённого ответа сервер выдерживает две минуты перед сверкой,
поскольку запрос ещё может завершаться на стороне Ozon. Единственный активный
сервер Пульта защищён общей блокировкой PostgreSQL. Транзакционную гарантию
ровно одного исполнения внешнего запроса сам Ozon API здесь не предоставляет.
Журнал и расписания находятся в локальном PostgreSQL, а ключи остаются в
существующем хранилище DPAPI. В Git их не сохраняют.

## Что использовано из изучения XWAY

XWAY связывает кампании, товары, статистику, ограничения и автоматические
правила. Его внутренний алгоритм закрыт; эта реализация не воспроизводит
неизвестную стратегию AI. Пока нет автоматического распределения бюджета,
управления ставкой по ДРР, дневного лимита на товар и оптимизации прибыли.
