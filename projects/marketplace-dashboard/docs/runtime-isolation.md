# Изолированный запуск разработки

Безопасный интерактивный режим поднимает только HTML и API реестра модулей на
случайном loopback-порту:

```powershell
node scripts/dev-isolated.cjs --preview
```

Команда печатает фактический URL. Preview не открывает PostgreSQL, не обращается к
маркетплейсам, не запускает фоновые задачи и передаёт модульным маршрутам пустой
контекст без `db`. В нём включены модули `developmentOnly`; переменная
`PULT_DEV_MODULES=1` устанавливается только на время создания dev runtime. Для
страниц модулей preview отдаёт из `dist` только `/module-ui.css`, `/module-ui.js`
и `/seller-shell.css`; другие пути и символические ссылки не обслуживаются.

Без `--preview` `scripts/dev-isolated.cjs` проверяет текущую сборку с существующим
пользовательским DPAPI bootstrap и по умолчанию не открывает сетевые порты:

```powershell
node scripts/dev-isolated.cjs --runtime-root C:\path\to\installed-pult
```

Вместо корня рабочего приложения можно передать точный путь через
`--bootstrap-file` или переменные `PULT_RUNTIME_ROOT` / `PULT_DEV_BOOTSTRAP_FILE`.
Файл используется по месту: команда не читает открытые секреты, не копирует его в
репозиторий и не выводит путь или содержимое в журнал. Расшифровку выполняет
существующий `storage/postgres-connection.cjs` через Windows DPAPI CurrentUser.

Проверка использует случайные loopback-порты (`0`) и не запускает listeners.
Порты рабочего приложения 4317 и 4319 запрещены. Для фактического запуска нужен
явный флаг, а Node следует запустить с тем же лимитом памяти, что и рабочий Пульт:

```powershell
node --max-old-space-size=8192 scripts/dev-isolated.cjs --runtime-root C:\path\to\installed-pult --run-shared-data
```

Такой процесс использует отдельные HTTP-порты, но существующий bootstrap подключает
его к той же базе `pult`. Он может конфликтовать с production advisory lease,
выполнять фоновые задачи и менять общие бизнес-данные. Для обычной разработки
модулей используйте `--preview`. Для полной изоляции данных нужна отдельно
подготовленная база и совместимое расширение валидатора bootstrap; текущая команда
намеренно не создаёт и не сохраняет новые учётные данные.

## Ветки и рабочий runtime

Одна задача использует одну ветку и отдельный Git worktree. Перед началом проверьте `git status` в исходном checkout, получите актуальный `origin/main` и создайте новый worktree; чужие незавершённые изменения не переносите и не очищайте. Для проверки страницы и API нового модуля используйте `npm run dev:isolated -- --preview` в его worktree.

Рабочий Пульт должен оставаться в собственной чистой deployment-копии на проверенном SHA. После `verify:module`, нужных тестов, полного `node scripts/check.cjs` и review диффа публикуйте ветку/PR. Развёртывание — отдельное действие: выбрать утверждённый SHA в deployment worktree, проверить совместимость локального DPAPI bootstrap и миграций, остановить прежний процесс штатно и запустить новую версию. Не переключайте ветку и не редактируйте файлы под работающим процессом; сохранение кода в GitHub само по себе не меняет runtime.
