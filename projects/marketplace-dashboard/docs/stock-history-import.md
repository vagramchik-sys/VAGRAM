# История остатков из Control Seller

В самостоятельном «Пульте» добавлена страница `/stock-history.html`. Ссылка из карточки товара передаёт магазин и точный SKU. Отчёт показывает исходные значения с датой дневной записи и отдельным временем наблюдения по Москве.

## Источники

| Источник | Назначение |
| --- | --- |
| `ozon-product-daily-snapshots.json` | Дневные товарные и складские снимки; `stockExact` и `warehouseExact` сохраняются в качестве данных |
| `ozon-cabinet-stock-core.json` | Последние товарные и складские снимки кабинета; устаревшая складская часть имеет собственное время |
| `ozon-seller-stock-core.json` | Архивные складские строки Seller API с исходной датой |
| `cluster-supply-last-good.json` | Последние сохранённые ответы API по складам и кластерам |
| `stock-audit/*.jsonl` | Завершённые проверяемые сборы; незавершённые попытки не выдаются за полные снимки |
| `stock-api-diagnostics/*.json` | Исходные складские строки диагностических ответов API; полнота каталога не подтверждена |

Наборы могут пересекаться. Они выбираются по одному и не суммируются. «Остаток источника» не равен доступному к продаже остатку. Резерв не выводится из других статусов. Неизвестные значения остаются неизвестными, настоящий ноль сохраняется. Неполные и устаревшие снимки имеют явную отметку. Более полная история внутри SQL-резервной копии требует отдельного извлечения; файловый импорт её не заменяет.

## Хранение и повторный импорт

Данные находятся только в `.private/history/stocks.sqlite`. Исходные файлы, контрольные суммы и явное соответствие магазинов архивируются в `.private/stock-history-imports`. Эти папки не публикуются в GitHub. Текущие `.private/data-*.json`, история продаж и настройки подключений не заменяются.

`scripts/import-control-stock-history.cjs` принимает `--source` (папка данных экспорта), `--private` (приватная папка Пульта), `--mapping` (JSON соответствия магазинов). Без `--apply` выполняется только разбор. Соответствие имеет вид `{ "source-store": { "id": "target-store", "name": "Название магазина" } }` и должно быть проверено до применения.

Сначала сохраняются оригиналы, затем нормализованные строки записываются одной транзакцией. Повтор идентичного импорта не удваивает историю. Одинаковые строки в последующих импортах получают дополнительную запись о происхождении. Отличающиеся значения не перезаписывают предыдущие наблюдения. Ошибки разбора и отбраковки фиксируются в отчёте импорта.

API `GET /api/stock-history/status`, `/report` и `/export` работают в существующей сессии Пульта. CSV использует те же фильтры, что и таблица, и включает весь выбранный набор, а не только видимую страницу. Запись данных через эти маршруты не предусмотрена.

Импорт не запускает исходные скрипты экспорта, не обращается к маркетплейсам и не восстанавливает исходную SQL-базу. Новый серверный маршрут начинает работать после штатного обновления процесса Пульта.
