# Работа с VAGRAM

Пишите пользователю по-русски, короткими абзацами. Выполняйте только запрос пользователя; не запускайте дополнительные задачи или фоновые процессы без необходимости.

## Код и сохранение

- Общий репозиторий: https://github.com/vagramchik-sys/VAGRAM, основная ветка `main`.
- Перед работой прочитайте `docs/workflow/README.md`, проверьте Git status и получите актуальный `origin/main`. Сохраняйте незавершенные изменения. Не используйте force push, reset --hard, clean или автоматическое разрешение конфликтов выбором одной стороны.
- Для независимых задач используйте отдельные ветки/worktree. Не редактируйте общую рабочую копию одновременно из нескольких задач.
- После завершения авторизованного изменения проверьте относящийся к нему код, затем сохраните только завершенные изменения этой задачи в GitHub. Пользователь выбрал этот репозиторий для постоянного хранения проектов; повторное подтверждение обычного сохранения кода не требуется. Публикация сайта, изменение внешних бизнес-данных и раскрытие секретов этим не разрешены.
- Для старых подключенных папок используйте `scripts/vagram.cjs`: update перед редактированием, prepare после завершения, затем публикация через GitHub plugin и ack. Не собирайте незавершенную работу других задач.
- Для обычного checkout используйте Git, когда доступ настроен; при отсутствии терминальной авторизации используйте уже подключенный GitHub plugin. Не извлекайте токены из файлов приложения и не просите пересылать их в чат.
- Перед публикацией выполните `node scripts/check.cjs` в точной публикуемой версии. При конфликтах с новой удаленной версией обновите основу и повторно проверьте результат. Никогда не заменяйте удаленное дерево целиком старой локальной копией.
- GitHub API: создавайте дерево с `base_tree_sha` актуальной основы и только измененными путями, коммит с этой основой в качестве родителя и обновляйте ref с `force: false`. Нефорсированное отклонение означает, что другой автор уже сохранил изменения: пересоберите результат на новой основе.
- После записи проверьте удаленный SHA/содержимое, сообщите ссылку на коммит. Не называйте локальный коммит или подготовленный payload опубликованным.

## Данные

Репозиторий публичный. Не добавляйте `.private`, `data`, `.env`, cookies, ключи, рабочие базы, журналы, пользовательские переписки и локальные настройки подключений. Сканер шаблонов секретов — дополнительная проверка, а не гарантия; просматривайте diff перед публикацией.

Работающие приложения используют прежние папки и отдельные базы. Сохранение кода в GitHub не является развертыванием и не требует перезапуска сервера. ИИ-директора внутри приложения не получают автоматически доступ к репозиторию.
